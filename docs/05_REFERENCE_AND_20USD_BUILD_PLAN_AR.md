## مسار التنفيذ الاقتصادي
1. Codex/GitHub/Codespace: الشيفرة والكتالوج والأصول والتوثيق. Codespace الموجود فُتح مجددًا؛ أظهر الفحص 7.8GiB ذاكرة وقرابة 19GB مساحة متاحة. لم يعثر `command -v` على Unity أو adb.
2. المسار الأول المرشح للبناء: Unity Build Automation بحصة الحساب المجانية المتاحة فعليًا. وفق صفحة Unity الرسمية توجد مخصصات شهرية: 200 Windows Micro و100 Linux Micro و100 Mac Standard، و25GB تخزين و100GB egress. هذه مخصصات عامة مشتركة بالحساب/المؤسسة وليست رصيد هذا المشروع المثبت.
3. فتح Unity Cloud أعاد إلى صفحة تسجيل الدخول؛ لم يتحقق رصيد الحساب أو أهلية الترخيص أو دعم نسخة 6000.3.25f1 على الخدمة.
4. بعد تسجيل الدخول: اختر مؤسسة EVENTO الصحيحة، افحص الاستهلاك وحدود الإنفاق، ثم اربط هذا المستودع فقط بفرع العمل. أي مطالبة بصلاحية أوسع أو شروط جديدة تُراجع عند ظهورها.
5. إعداد هدف UBA: Android / APK تطويري، جذر المشروع `/`، Unity `6000.3.25f1`، IL2CPP/ARM64، scene من EditorBuildSettings، pre-export `OctopusS1CloudBuild.PreExport`. لا تحدد قائمة مشاهد قديمة تتجاوز المشهد المولد.
6. عطّل تشغيل البناء عند push أو جدول متكرر، واجعل التزام المصدر المقصود ظاهرًا في سجل البناء. محاولة واحدة ثم افحص الخطأ قبل إعادة المحاولة.
7. يفحص hook أن الهدف Android، ويولّد مشهد البداية ويطبق إعدادات البناء المشتركة دون استدعاء BuildPlayer مرة ثانية. لم يُختبر داخل Unity بعد.
8. إن لم تتوفر حصة أو نسخة المحرر أو ضبط يضمن البقاء ضمن السقف، يعود المسار إلى مضيف Unity مرخص موجود أو عرض إيجار محدد يغطي جميع الرسوم مع وقت إيقاف نهائي. لا تستأجر GPU لمجرد بناء APK.
9. بعد نجاح البناء سجّل commit وإصدار Unity وSHA-256 ونتائج PlayMode ثم نزّل APK وثبته على هاتف Android ARM64 مصرح به. نجاح UBA وحده لا يمنح قبول G2/G3.

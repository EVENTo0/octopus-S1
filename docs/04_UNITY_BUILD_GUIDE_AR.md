# مسار بناء Unity وAPK — Octopus S1

**نسخة المحرّك المسجلة في ProjectVersion.txt:** Unity 6000.3.25f1 (Unity 6.3 LTS). لم يثبت المحرّك في Codespace.  
المصدر: صفحة إصدار Unity الرسمية ورقم التغييرات المرفق مع هذا الإصدار.

## هيكل النموذج الأولي

- `Assets/Scripts/OctopusS1Prototype.cs`: مشهد اختبار يتولد عند التشغيل، مع حركة، رفيق أخطبوط مؤقت، ثلاث خلايا، برج إرسال ونقطة إخلاء.
- `Assets/Editor/OctopusS1SceneBuilder.cs`: من قائمة Unity اختر `Octopus S1 → Build Prototype Scene` لإنشاء مشهد `Assets/Scenes/OctopusS1Prototype.unity` وإضافته إلى Build Settings.
- كل الهندسة في هذا النموذج **Placeholder**. لا تمثل جودة فنية أو أصولًا نهائية.
- ضوابط الاختبار: WASD/الأسهم وQ/E على سطح المكتب؛ أزرار لمس أولية على الشاشة.

## متطلبات Android

لبناء تطبيق Android من Unity، توثق Unity اعتماد الوحدة Android Build Support وAndroid SDK وAndroid NDK وJDK. تتولى نسخة Unity المختارة تحديد النسخ المتوافقة. يثبت Android Build Support مع Unity Hub/Editor بدل تركيب NDK عشوائيًا. بعد البناء نختبر APK على جهاز حقيقي، فالمحاكي أو نجاح Gradle لا يكفي لقبول G3.

## خطوات التطوير في Codespace

1. تثبيت Unity 6000.3.25f1 على عامل Linux/Windows يدعمها، مع Android Build Support.
2. توفير ترخيص Unity بالطريقة المدعومة. لا يودع ملف الترخيص أو الأسرار في Git.
3. في محرر Unity، تشغيل `Octopus S1 → Build Prototype Scene`.
4. اختيار Android وبناء APK تجريبي.
5. تثبيت APK على جهاز Android، تسجيل النسخة والجهاز والالتزام، وتوثيق سيناريو المهمة والفشل والأداء.
6. إصلاح الملاحظات وإعادة القياس قبل اعتماد G3.

بيئة Codespace الحالية لا يظهر فيها أمر Unity أو adb ضمن PATH. لذلك هذا الدليل إعداد مقترح؛ لا يثبت أن المحرك أو وحدات Android موجودة في البيئة، ولا يسجل نجاح بناء.

## المسار الدفعي المضاف — 26 أكتوبر 2026

فُحص أساس PR عند الالتزام `71a381352176c50aa58fe975ff274d3ac92ea267`.
لا يوجد ملف مشهد محفوظ في الأساس؛ إنشاء المشهد مقصود من السكربت.
أضيفت وحدات Unity المدمجة المطلوبة (physics/audio/imgui/inputlegacy/jsonserialize)
ومدخلات Horizontal/Vertical الصريحة، واختبار PlayMode لدورة جمع الخلايا ثم البرج ثم الإخلاء،
مع رفض التفعيل المبكر. يبقى اختبار الحركة واللمس والأداء على الجهاز مطلوبًا.
تُنشأ مادة Standard داخل Resources لضمان تضمين shader الذي يستدعيه الكود بالاسم.

على جهاز موجود ومرخص، ثبّت Unity **6000.3.25f1** مع Android Build Support
وSDK/NDK/OpenJDK المطابقة من Hub، واضبط مسار المحرر:
```bash
export UNITY_EDITOR=/absolute/path/to/Unity
python3 -m unittest discover -s tests -v
scripts/unity-build.sh test
scripts/unity-build.sh build
```

الأمر الأخير يعيد إنشاء المشهد آليًا، يضيفه للبناء، ويختار Android/IL2CPP/ARM64،
min SDK 26، اتجاه landscape، APK تطويري بتوقيع debug محلي، الإصدار 0.1.0/code 1.
يجب أن تكون مصادر Unity ملتزمًا بها قبل البناء؛ التوليد اللاحق يحدث داخل Unity.
يفشل الأمر عند عدم دعم Android أو فشل البناء. لا يُستعمل توقيع إصدار أو نشر.
النواتج في Builds/Android: APK وSHA-256 وbuild.json يسجل التزام المصدر والإصدار.
هذه قابلية إعادة تنفيذ المسار، وليست ضمان تطابق بايتات APK بين المضيفين.
الاختبارات تعمل منفصلة دون -quit؛ يتحقق السكربت من XML ويرفض غياب الاختبارات أو فشلها.
فشل الترجمة يمنع Unity من الوصول لأمر البناء؛ راجع Logs/tests.log وLogs/android.log.
لا تتجاوز الاختبارات إذا فشلت.

### نتيجة التحقق الفعلية

- نجح فحص Python لوحدات المشروع ومدخل البناء (اختباران)، وصياغة Bash وgit diff --check.
  هذه فحوص إعداد فقط وليست مترجم C#.
- لم يُنفذ استيراد Unity أو ترجمة C# أو اختبار PlayMode أو Android build.
  ملف packages-lock سيولده أول استيراد ناجح ويجب مراجعته وإيداعه لتثبيت الاعتمادات المحلولة.
- لا APK موجود؛ لذلك لا بصمة APK ولا اختبار جهاز ولا قبول G2/G3.
- المتبقي: مضيف Unity مرخص بالإصدار المحدد ووحدات Android، استعادة الحزم،
  تشغيل الاختبارات والبناء أعلاه، ثم جهاز Android ARM64 مصرح به.
- على الجهاز: سجّل SHA والنسخة وبصمة APK وطراز الجهاز وAndroid، وثّق تثبيت
  adb install -r، الحركة بأزرار اللمس، جمع كل خلية مرة واحدة، رفض البرج قبل الثالثة،
  تفعيل البرج، رفض الإخلاء قبله وإكمال المهمة بعده، ثم logcat والأداء.
  لم يتوفر جهاز مصرح به في هذه الجلسة.

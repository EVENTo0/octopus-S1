## تثبيت المحرر والتحقق من C#
- أكد API الرسمي نسخة 6000.3.25f1 ومراجعتها e1dba0a9aba4:
  https://services.api.unity.com/unity/editor/release/v1/releases?version=6000.3.25f1&limit=1
- نزّل أرشيف Linux الرسمي (4,536,554,312 بايت) إلى
  /workspace/unity-host وفُحص MD5 بمقارنته بقيمة API:
  `ea96fdeba5dca12a17b4b57945649d5f`.
  هذه بصمة أرشيف المحرر وليست بصمة APK.
- فُك الأرشيف، وأعاد `Editor/Unity -version`: `6000.3.25f1`.
  يوجد LinuxStandaloneSupport فقط؛ لم تُثبت وحدات Android بعد.
- نجحت ترجمة C# مستقلة لمجموعة اللعبة ولجميع ملفات Editor الثلاثة،
  بما فيها Cloud hook، باستخدام Roslyn المرفق ومراجع Unity الأصلية.
  عولج تحذير SetApplicationIdentifier باستخدام NamedBuildTarget.
- الفحص قابل للتكرار على Linux بعد استخراج المحرر:
  ```bash
  python3 scripts/check_csharp.py --editor /workspace/unity-host/Editor
  ```
  تكتب ملفات DLL وresponse في Logs/csharp محليًا. لا تُرفع المحرر أو مخرجاته إلى Git.
  هذا فحص مرجعي مكمل فقط: لا يستورد المشروع ولا يحل الحزم ولا يترجم هدف
  Android/IL2CPP ولا يشغّل اختبارات أو مشهدًا؛ ليست نتيجته قبول G2/G3.

## محاولة اختبارات المحرك
نُفذ:
```bash
UNITY_EDITOR=/workspace/unity-host/Editor/Unity timeout 90s scripts/unity-build.sh test
```
خرج المحرر برمز 198 قبل تنفيذ الاختبارات. السجل Logs/tests.log يتضمن:
```text
[Licensing::Module] Error: 'com.unity.editor.headless' was not found.
No valid Unity Editor license found. Please activate your license.
```
ظهرت أيضًا أخطاء إنشاء مجلدات إعداد Unity داخل home المقيد في البيئة.
لم نغير الصلاحيات أو نحاول تجاوز الترخيص. تشغيل فعلي يحتاج تفعيلًا مدعومًا
ومجلد إعداد قابلًا للكتابة على مضيف مناسب. توضح Unity أن تفعيل Personal
يكون بتسجيل الدخول إلى Hub؛ طريقة Pro عبر CLI ليست بديلًا لتفعيل Personal:
https://docs.unity3d.com/6000.3/Documentation/Manual/ManagingYourUnityLicense.html

`5aa90efb344b8cc71adaa89460bf9c9d9d9e96f2`.

يوجد خطأ نسخ في محدد الالتزام المسجل سابقًا في الوثيقة 05:
`5aa90efb344b8cc71adaa89460bf9c9d9e96f2` (38 خانة).
المحدد الكامل أعلاه 40 خانة، بينما الصيغة المدونة لا تحل إلى commit محليًا.
هذا يثبت خللًا في التوثيق، ولا يثبت أن القيمة نفسها دخلت إعداد Unity Cloud؛
يلزم مقارنة صفحة المحاولة والسجل الأصلي قبل نسب فشل checkout لهذا السبب.
لا تغيّر شيفرة اللعبة لمعالجة خطأ Git غير مشخص.

قبل إعادة المحاولة السحابية:
1. تحقق من إعداد مصدر المشروع واستخدم الفرع الموجود، واحصل على SHA كامل من
   `git rev-parse origin/codex/octopus-s1-charter-and-prototype` بعد fetch.
2. راجع سجل checkout الكامل وقيمة selector الفعلية، واعتماد المصدر الصالح؛
   الوثيقة 05 تسجل أن الاعتماد السابق أُلغي بعد المحاولة الأولى.
3. تحقق من رصيد الحصة الحالية وتكلفة المحاولة وحدود الإيقاف ضمن 20 USD،
   مع بقاء Auto-build والجدول معطلين.
4. شغّل محاولة واحدة فقط بعد إصلاح إعداد المصدر. لا توجد جلسة Unity Cloud
   أو اعتمادها متاحان لأدوات هذه الجلسة لإجراء ذلك التغيير.
